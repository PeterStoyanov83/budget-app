# HANDOFF — Моят Бюджет

## What this is
Bulgarian-language PWA personal budget tracker for a pensioner.
Single user per account. Dark theme. Mobile-first (max 480px).

## Repo
https://github.com/PeterStoyanov83/budget-app

## Current stack
- **Frontend**: Vanilla HTML/CSS/JS — `public/index.html` (single file, ~700 lines)
- **Backend**: Node.js + Express — `server.js`
- **Database**: SQLite via `better-sqlite3` — stored in `data/budget.db` (gitignored)
- **Auth**: `express-session` + `bcryptjs` — sessions stored in `data/sessions.db`
- **Deploy target**: Render.com — config in `render.yaml` (persistent disk at `/data`)

## File structure
```
server.js           Express API (register, login, logout, /api/data GET/PUT)
package.json        dependencies: express, express-session, connect-sqlite3, better-sqlite3, bcryptjs
render.yaml         one-click Render.com deploy config
public/
  index.html        full app — auth screen + 3 tabs (Бюджет / История / Съвети)
  sw.js             service worker, cache-first, skips /api/ routes
  manifest.json     PWA manifest
  icons/            icon-192.png + icon-512.png (generated by generate-icons.js)
generate-icons.js   node script — run: npm run icons (needs canvas devDep)
data/               gitignored — created at runtime by server
```

## API routes
| Method | Route | Auth | Description |
|--------|-------|------|-------------|
| POST | /api/register | — | create account, sets session |
| POST | /api/login | — | login, sets session |
| POST | /api/logout | ✓ | destroy session |
| GET | /api/me | ✓ | returns `{userId, username}` |
| GET | /api/data | ✓ | returns full allData JSON |
| PUT | /api/data | ✓ | saves full allData JSON |

## Data model
```json
{
  "2026_5": {
    "income": 800,
    "expenses": [ { "id":"e1", "cat":"fixed", "icon":"⚡", "name":"...", "amount":150, "note":"...", "enabled":true }, ... ],
    "notes": "бележки..."
  }
}
```
Month key: `{year}_{month}` — month is **0-indexed** (June = 5).
Default expenses: 12 rows across 5 categories (fixed/health/family/food/other).

## Auth / UX flow
1. App loads → calls `/api/me`
2. If session exists → show app directly
3. If not → show Bulgarian login/register screen (two tabs: Вход / Регистрация)
4. Header shows: `👤 username` + `✓ Запазено` flash + `Изход` button
5. Data auto-saves 1200ms after last change (debounced PUT to `/api/data`)

## Deploy to Render (steps for next session)
1. render.com → New Web Service → connect GitHub repo PeterStoyanov83/budget-app
2. Render reads `render.yaml` automatically — sets Node env, persistent disk, generates SESSION_SECRET
3. Click Deploy → get URL like `https://budget-app.onrender.com`
4. First visit: pensioner registers with Bulgarian name + 4-char password, done

## History of what was tried / why decisions were made
- **v1**: Static PWA + GitHub Gist as backend → rejected: too complex for pensioner (tokens, gists)
- **v2** (current): Express + SQLite + Bulgarian login screen → simple URL + username/password
- GitHub Pages was used briefly but dropped once backend was needed
- `render.yaml` includes a 1GB persistent disk so SQLite survives redeploys

## Known issues / next steps to consider
- Render free tier spins down after 15min inactivity (cold start ~30s) — upgrade to paid or use Railway if annoying
- No password reset flow yet
- No admin view to see all users
- Session cookie is 30 days — fine for single-device use
- `SESSION_SECRET` defaults to a hardcoded string if env var missing — fine for dev, Render auto-generates it
